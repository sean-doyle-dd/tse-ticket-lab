## Run the sandbox

This project reproduces the customer's environment as closely as a laptop can. It does **not** tell you what's wrong; that's your job.

1. Use a **sandbox org** API key, never a customer or production key:
   ```bash
   cp .env.example .env    # then set DD_API_KEY (and DD_SITE if not datadoghq.com)
   ```
2. Start it:
   ```bash
   docker compose up -d --build
   ```
3. Investigate the way you would with the customer. Read logs, run `agent status`, check the config, and compare what you see with what the customer reports.
4. When you think you've fixed it, run:
   ```bash
   ./verify.sh
   ```
5. To start over (this restores every file you may have edited):
   ```bash
   ./reset.sh
   ```
6. Clean up when you're done: `docker compose down -v`.
